# Чат

Описание инфраструктуры, функций и пользовательских сценариев работы в подсистеме "Чаты"

## Инфраструктура

Подсистема чатов является отдельным программным модулем, предоставляющим REST-интерфейс и socket.io v3 интерфейс. Также подсистема интегрирована с программным решением для обеспечения аудио- и видео-конференций Flashphoner.

### Чаты

- Swagger: `https://stage.naukotheka.ru/api/chat/static/index.html`
- Базовый URL REST-сервисов: `https://stage.naukotheka.ru/api/chat/v1`
- URL socket.io: `https://stage.naukotheka.ru/api/chat/socket.io`

### Flashphoner

- Базовый URL REST-сервисов и веб-сокетов: `https://stage.naukotheka.ru:8444/`

### OpenAPI-контракты (source of truth) и аудит

Скачанные со стейджа спецификации лежат в `docs/api/`:
- `docs/api/chat-openapi.json` — chat API (`…/api/chat/json`)
- `docs/api/core-openapi.json` — core API (`…/api/core/api-docs`)

Сверка наших Retrofit-сервисов с этими контрактами (расхождения версий, дрейф путей, пробелы) — в `docs/api-audit.md`. Обновлено 2026-08-11.

> **Socket.io — важно:** по факту сокет несёт **только событие `message`** (текст + `action.type`: read/delete/update/changeChat). Событий «печатает…»/typing и push-presence **нет** — это подтверждено wiki, OpenAPI и живым логом. Индикатор печати требует нового контракта с бэкендом. Онлайн-статус берётся REST-ом: `POST /api/chat/v1/users/status`.

## Вспомогательные функции

### Загрузка файлов

Отправка сообщений, имеющих файловое вложение происходит в два этапа:

#### Загрузка самого файла на сервер

Эндпойнт подсистемы core, возможна множественная загрузка:

`POST /api/core/files`

В результате будет возвращен массив с описателями файлов, из которого в дальнейшем потребуются атрибуты `id`.

Если требуется прикрепить файл без преобразований (сжатий), в исходном виде, то необходимо также указать параметр запроса `?raw`.

Пример ответа:

```json
[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "path": "/files/3fa85f64-5717-4562-b3fc-2c963f66afa6.jpg",
    "fileName": "avatar.jpg",
    "contentType": "image/jpeg",
    "fileSize": 123456,
    "fileKind": 1,
    "fileType": null
  }
]
```

#### Превью файла / сжатие

После загрузки файлов будут выполнены асинхронные преобразования:

- Если при загрузке параметр `raw` не передан, то изображения больше 1200 пикселей по ширине будут сжаты до 1200 пикселей.
- Для изображений и видео будут сгенерированы превью (наличие параметра `raw` на них не влияет).

Эндпоинты получения файлов:
- `GET /api/core/files/:fileId`
- `GET /api/core/s/:entity/:entityId/:subtype/:fileId`

Параметры превью:

| Параметр | Результат |
|----------|-----------|
| `?preview` | Изображение превью размером 300 пикселей по ширине. Для видео — первый ключевой кадр |
| `?preview=90` | Изображение превью с шириной 90 пикселей |
| `?preview=webp` | Изображение превью с шириной 300 пикселей в формате webp |

Для аудио- и видео-файлов будет выполнена попытка получить длительность. Если она была успешна, при отдаче сведений о файле будет возвращено поле `duration` в формате ISO 8601.

#### Прикрепление данных о загруженном файле к сообщению

При отправке сообщения через веб-сокет либо при редактировании через `PATCH /messages/update` нужно отправить в поле `files` массив с описателями файлов (`id` и `fileType`).

Пример:

```json
{
  "cType": 1,
  "dialog": 1234,
  "text": "Hello world",
  "files": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "fileType": 1
    }
  ]
}
```

Для файлов необходимо корректно указать подтип файла (`fileType`), чтобы они отображались в разделе "Медиа" диалога.

Голосовые сообщения: `cType = 4` для сообщения и `fileType = 21` для файла.

Поддерживаемые типы файлов (справочник #41):

| fileType | Описание |
|----------|----------|
| 1 | Изображение |
| 20 | Аудио-файл |
| 21 | Голосовое сообщение |
| 30 | Видео-файл |
| 100 | Обычный файл |

### Данные пользователя

Получение сведений о пользователе:
- `GET /api/core/user_profile/:userId`
- `GET /api/chats/v1/dialogs/info/:dialogId` — в массиве `users`

### Поиск пользователей

`GET /users/search`

Параметры:
- `searchField` — поиск по подстроке в ФИО или никнейме
- `limit` — размер страницы (по-умолчанию 10)
- `page` — номер страницы (по-умолчанию 1)

#### Атрибуты результата

- `status` — `{ isOnline: boolean, lastSeen: timestamp }`
- `permits` — массив разрешенных доступов (справочник 82)
- `group` — код логической группы (справочник 188):
  - `null` — группа не задана
  - `188:1` — последние пользователи с взаимодействиями
  - `188:2` — подписки без активного чата

#### Режим поиска по подстроке (имени)

Передать в `searchField` подстроку для поиска по ФИО или никнейму.

#### Режим рекомендаций

Параметр `searchField` **не передается**.

Результат содержит единый массив пользователей, отсортированный по группе:
1. Последние пользователи (`group = 188:1`) — от 0 до 6, только на первой странице
2. Подписки (`group = 188:2`) — размер до `limit`, с учетом `page`

Внутри каждой группы сортировка по ФИО, затем по никнейму.

### Приватность пользователей

Пользователи могут запретить добавлять себя в чат:
- `82:200` — разрешение на добавление в личный диалог
- `82:201` — разрешение на добавление в групповой

### Статус пользователей

`GET /users/status`

Возвращает текущий статус пользователя и время последнего появления онлайн.

### Отправка отметки о прочтении сообщения

#### Типы сообщений для счетчика

Отметку о прочтении нужно отправлять только для чужих или системных сообщений.

Счетчик непрочитанных: статус != 3 и тип ∈ {1, 2, 3, 4, 5, 7, 6003, 6004}.

При отметке нескольких id берется наибольшее, и все предшествующие чужие сообщения помечаются тем же статусом. При статусе 3 (прочитано) наибольшее id ставится в `lastReadMessageId`.

#### Статусы (справочник #71)

| num | term |
|-----|------|
| 1 | отправлено |
| 2 | доставлено |
| 3 | прочитано |

**Статус "Отправлено"** — автоматически при создании.

**Статус "Доставлено"** — клиенты, получившие сообщение.

**Статус "Прочитано"** — клиенты, отобразившие сообщение во вью-порте.

Поле `read` трактуется по-разному:
- Для **своих** сообщений — максимальный статус от других пользователей (галочки)
- Для **чужих** — статус, выставленный текущим пользователем

Обработка:
- Свои сообщения — одна, две серые или две синие галочки
- Чужие — отправить отметку о прочтении
- Системные / о звонках — галочки не отображать, но пометку отправлять

#### API отметки о прочтении

`PATCH /messages/read`

Передается id диалога, список id сообщений и значение статуса.

Все сообщения автоматически помечаются прочитанными при выходе из чата. Понизить статус нельзя.

### Удаление сообщений

Одно сообщение: `DELETE /messages/:messageId`

Несколько:

```
DELETE /messages/
{
  "messages": [12345, 12346]
}
```

403 — сообщения удалены или пользователь не автор.

#### Удаление "для себя"

Параметр `?forMe` или `?forMe=true`. Можно помечать свои и чужие сообщения. 404 — все сообщения уже скрыты.

### Обработка входящих сообщений из socket.io

#### Формат сообщений

```json
{
  "id": 123,
  "dialog": 456,
  "cType": 1,
  "text": "Hello",
  "owner": "uuid",
  "files": [
    { "id": "...", "path": "...", "filename": "...", "contentType": "...", "fileType": "..." }
  ],
  "action": {
    "type": "read",
    "name": "...",
    "messageId": 123,
    "messages": [1, 2, 3],
    "messageStatus": 3
  }
}
```

#### Отметка о прочтении (входящие)

Условия:
- `owner` не текущий пользователь
- `id` не пуст

Действия:
- Статус "получено" (2) — если диалог не активен
- Статус "прочитано" (3) — если сообщение в активном диалоге

#### Текстовое сообщение (тип 1)

Поместить в массив сообщений чата. Если чат не загружен — получить информацию.

#### Системное сообщение (тип 5)

По `action.type`:
- `read` — установить статус `action.messageStatus` для `action.messages`
- `delete` — удалить сообщение `action.messageId`
- `update` — обновить сообщение `action.messageId`
- `changeChat` — обновить атрибуты диалога из `action.name`, `action.image`, `action.users`

## Ответы и пересылка сообщений

### Ответы на сообщения

Через сокет, заполнить `answered` — id цитируемого сообщения. При редактировании изменить `answered` нельзя.

Превью ответа (`ansPreview`):

| Поле | Описание |
|------|----------|
| i | ID сообщения |
| mt | Тип сообщения (справочник #109) |
| o | Автор: `{ i, fn, im }` |
| t | Начало текста (до 200 символов) |
| f | Первый файл: `{ path, fileName, fileType }` |
| st | Статистика файлов: `[{ c, ft }]` |

```json
{
  "ansPreview": {
    "i": 123456,
    "mt": 1,
    "o": {
      "i": "uuid",
      "fn": "Иван Иванов",
      "im": "/s/users/.../avatar/....png"
    },
    "t": "Lorem ipsum dolor sit amet",
    "f": {
      "path": "/s/Messages/12345/image/....jpeg",
      "fileName": "test_image.jpeg",
      "fileType": 1
    },
    "st": [
      { "c": 1, "ft": 1 },
      { "c": 2, "ft": 100 }
    ]
  }
}
```

### Пересылка сообщений

Через сокет, заполнить `forwarded` (один id) или `forwardedn` (массив), указать `dialog` или `dialogs`.

Можно добавить `text` — будет создано дополнительное сообщение.

Из пересылаемого копируются: `cType`, `files`, `text`, `answered`.

### CRUD

`POST/PATCH/DELETE /dialogs/folder/<:folderId>`

`GET /dialogs/folder/:folderId` — полный список `dialogIds` + первые 10 описателей `dialogs`.

### Список диалогов в папке

`GET /dialogs/folder/:folderId/dialogs?limit=10&page=1`

Дополнительное поле `folderNames` — до трех названий других папок.

### Все папки

`GET /dialogs/folder`

Папка `id = -1` (Все) в начале, `id = -2` (Заблокированные) в конце.

### Порядок папок

`PATCH /dialogs/folder/reorder`

```json
{ "folderIds": [21, 22, 23, 24, 25] }
```

### Фильтрация списка диалогов

`GET /dialogs` с параметром `folderId`. `-2` — заблокированные.

### Пометить диалоги в папке как прочитанные

`PATCH /dialogs/folder/:folderId/set-read`

## Опросы

### Общее описание

Идентификаторы опросов и их элементов — UUID.

### Формат превью

```json
{
  "poll": {
    "i": "uuid",
    "aa": ["option-uuid"],
    "oo": [
      {
        "i": "option-uuid",
        "r": true,
        "v": "Опция 1",
        "d": "Описание правильного ответа",
        "pv": 33,
        "ord": 1
      }
    ]
  }
}
```

Поля:
- `i` — id сущности
- `aa` — выбранные пользователем варианты
- `oo` — список вариантов
- `v` — значение варианта
- `pv` — процент голосов
- `ord` — порядковая позиция
- `r` — правильный ответ (только для завершенного)
- `d` — описание правильного ответа

### Use Cases

#### Создание и размещение опроса

1. `POST /dialogs/poll` — создать опрос с флагами и вариантами
2. Отправить сообщение `cType = 9` с `pollId` в сокет
3. В сокет придет сообщение с полем `poll`

#### Ответы на опрос

- Флаг `multipleAnswers` управляет множественным выбором
- `PUT /dialogs/poll/:pollId/answer` — массив id вариантов (пустой = отозвать)
- Пересылка через `forwarded[n]`, заполнять `pollId` нельзя

#### Детали опроса

- `GET /dialogs/poll/:id` — только автору
- `GET /poll/:pollId/answer-users/:optionId` — проголосовавшие
- `POST /dialogs/poll/:pollId/stop` — завершить (только автор)
- `DELETE /dialogs/poll/:pollId` — удалить (только автор)
