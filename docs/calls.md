# Аудио-, видео-звонки

В основе архитектуры лежит roomApi из Flashphoner.
- Веб SDK: https://docs.flashphoner.com/display/WEBSDK2RU/Web+SDK+2.0+-+RU
- iOS SDK: https://docs.flashphoner.com/display/IOSSDK2RU/iOS+SDK+2.0+-+RU
- Android SDK: https://docs.flashphoner.com/display/ANDROIDSDK11RU/Android+SDK+1.1+-+RU

При начале звонка на клиенте создаётся комната (room). Принимающий звонок пользователь инициализирует комнату с тем же id и они оба оказываются в одной конференции.

---

## Процесс создания комнаты

1. `RoomApi.connect` создаёт сессию. URL веб-сервера FF: `wss://stage.naukotheka.ru:8443`.
2. После успешного создания сессии вызывается метод `join`, куда передаётся имя комнаты = **id диалога**.
3. Когда комната инициализирована, бэкенд реагирует на событие `onPublish` и рассылает широковещательное сообщение `cType 2` (аудио) или `cType 3` (видео). В сообщении: поле `owner` — id звонящего, `dialog` — id диалога.
4. Ответивший повторяет шаги 1–2 с `dialogId` из сообщения о входящем звонке как `roomName`.
5. Если никто не ответил в течение **30 секунд** — звонок завершается.

## Завершение звонка (актуально)

> Сверено с wiki «Звонки» 2026-08-11. Старый способ «отправить `cType = 6`/`6002`
> вручную» **устарел** (в wiki зачёркнут). Теперь только REST.

Завершить звонок для всех (администратор/организатор, либо любой участник в
1-на-1):

```
POST /calls/dialog/:dialog/stop      (либо POST /calls/:callId/stop)
```

Бэк: завершает все WCS-сессии, ставит статусы Участвовал (2)/Пропустил (8),
рассылает `cType 6` (CALL_ENDED) всем и `cType 6004` пропустившим окончание,
останавливает запись. Не ответившим при этом уходит `cType 6002` (KICK).

Разница «выход» vs «завершение»:
- **Выход** участника — WCS `Room.leave()` (см. §6.1). Звонок продолжается для
  остальных; если сессий администраторов не осталось — авто-стоп через 30 сек.
- **Завершение для всех** — REST `stop` выше. В 1-на-1 это единственный способ
  завершить звонок у собеседника СРАЗУ (иначе он висит до таймаута зависшего
  звонка).

Для отказа от входящего звонка — `cType 6001` (в сокет).

## Управление участниками

### Чтение состояния участников начатого/активного звонка

```
GET /calls/dialog/:dialogId/participants
```

| Параметр | Описание |
|---|---|
| `details` | Битовая маска: `1` — показать `fullName` и `imageUrl` |

Пример ответа:
```json
[
  {
    "id": 2678,
    "call": 3405,
    "user": "bbcdeaa7-4e69-49e8-8dea-a74e6959e83e",
    "fullName": "Имя Отчество Фамилия",
    "imageUrl": "/s/users/.../avatar/....jpg",
    "status": 5,
    "states": [
      {
        "id": 6070,
        "call": 3405,
        "user": "bbcdeaa7-4e69-49e8-8dea-a74e6959e83e",
        "mediaSessionId": "e7a487d7-81e5-4504-a487-d781e5c5044d",
        "state": { "micOn": true, "camOn": false }
      }
    ],
    "roles": ["37:301"],
    "permits": ["82:601","82:602","82:603","82:604","82:605","82:606","82:607","82:608","82:609","82:610","82:611","82:612"]
  }
]
```

Пермиты всех участников видят только администраторы. Обычный пользователь видит свои роли/пермиты, у остальных — только роли.

### Состояние одного участника

```
GET /calls/dialog/:dialogId/participant
```

| Параметр | Описание |
|---|---|
| `userId` | UUID пользователя. Если не задан — возвращает данные вызывающего |
| `details` | Битовая маска: `1` — показать `fullName` и `imageUrl` |

## Статусы участников

### Изменение статуса (для администраторов и организатора)

```
PATCH /calls/dialog/:dialogId/status
```
```json
{ "user": "bbcdeaa7-...", "status": 5 }
```

### Сообщение об изменении статуса (`cType: 2008`)

```json
{
  "dialog": 1234,
  "cType": 2008,
  "statusUpdates": [
    { "status": 5, "users": ["bbcdeaa7-..."] },
    { "status": 4, "users": ["0cb049dd-..."] }
  ]
}
```

### Доступные статусы (#190)

| № | Описание |
|---|---|
| 1 | Приглашён |
| 2 | Участвовал в звонке (конечный) |
| 3 | Отклонил звонок (конечный) |
| 4 | Пропустил вызов (начало звонка) |
| 5 | Участвует в звонке |
| 6 | Ожидает в лобби |
| 7 | Удалён из звонка (конечный) |
| 8 | Пропустил звонок (конечный) |

### Типичные переходы статусов

- Приглашён → Участвует → Участвовал
- Приглашён → Отклонил
- Приглашён → Пропустил вызов → В лобби → Участвует → Участвовал
- Приглашён → Участвует → Исключён

### Автоматическая установка статусов

| Событие | Статусы |
|---|---|
| Первая сессия FF от организатора | Приглашён (1) для всех участников чата |
| Вторая сессия FF от ответившего | Участвует (5) для организатора и ответившего |
| Последующие сессии FF | Участвует (5) для последующих |
| 30 секунд без ответа | В лобби (6) для опоздавшего, сессия FF прекращается |
| 30 секунд после выхода всех администраторов | Участвовал (2) / Пропустил (8) |

### Ручная установка администраторами

| Предусловие | Действие | Результат |
|---|---|---|
| Участник в лобби (6) | Администратор приглашает | Статус Участвует (5) через REST |
| Участник участвует (5) | Администратор исключает | Статус Исключён (7) через REST |

```
PATCH /calls/dialog/:dialogId/permits
```
```json

  "addPermits": ["82:605"],
  "delPermits": ["82:608"]

```

```json

  "dialog": 1234,
  "cType": 2007,
  "permitsUpdate": {
    "user": "bbcdeaa7-...",
    "role": "37:302",
    "addPermits": ["82:605"],
    "delPermits": ["82:608"]
```

```
PATCH /calls/dialog/:dialogId/state
```

```json
  "user": "bbcdeaa7-...",
  "mediaSessionId": "e7a487d7-...",
```

```json
    {
      "user": "bbcdeaa7-...",
      "mediaSessionId": "e7a487d7-...",

  ]

```

## Use Case: управление состояниями, статусами и ролями

### 1. Начало звонка

1. REST: `GET /dialogs/info/:dialogId` — получить аватары участников
2. WCS: инициировать медиа-поток, создать комнату
3. WS: получить `cType 2` или `3` (звонок начат), в сообщении должен быть id звонка
4. Бэк: инициатор получает роль Организатор `37:301`, остальные — Участник `37:303`
5. WS: ожидать `2001` (звонок активен) или `6` (завершён через 30 сек)
6. REST: при получении `2001` — `GET /calls/dialog/:dialog/participants`

### 2. Ответ на звонок (первый ответивший)

1. WCS: создать сессию и комнату
2. WS: ожидать `2001`
3. REST: `GET /calls/dialog/:dialog/participants`

#### 2.1 Отклонение входящего звонка

1. WS: отправить `6001`
2. WS: получить `2008` со статусом Отклонил (3)

### 3. Подключение к активному звонку (второй и далее)

1. WS: есть `2001` или поле `activeCall` в чате; сообщение `6003` **не** получено
2. WCS: создать комнату
3. WS: получить `2008` — Участвует (5)
4. REST: получить участников

#### 3.1 Попытка подключиться с необработанным `6003`

1. WCS: создать комнату
2. Бэк: участник ещё в статусе Приглашён (1), но таймаут прошёл → сессия принудительно останавливается, статус → В лобби (6)
3. WS: `2008` со статусом В лобби (6)
4. REST: получить участников, ожидать `2004`

### 4. Подключение после таймаута

1. WS: уже получен `6003`
2. WS: отправить `2002` (запрос на присоединение), ожидать ответа
3. WS: `2008` — статус → В лобби (6)

#### 4.0 Разрешение от администратора

```json
{ "cType": 2003, "dialog": 1234, "users": ["bbcdeaa7-..."], "text": null }
```
Бэк: меняет статус → Приглашён (1), отправляет `2004` приглашённым.

#### 4.1 Получено разрешение (2004)

1. WCS: создать комнату
2. REST: `GET /calls/dialog/:dialog/participants`

#### 4.2 Разрешение не получено

WS: ожидать `2004` от администратора (участник в статусе В лобби (6)).

### 5. Изменение своего состояния

1. REST: `PATCH /calls/dialog/:dialog/state` — передать `micOn`, `camOn`, `handUp` и т.д. с `mediaSessionId`. При запрете — `403`.
2. WS: `2006` рассылается всем участникам.

### 6. Выход из звонка

#### 6.1 Правильный способ

1. WCS: `Room.leave()`
2. Бэк: завершает все сессии участника, статус → Участвовал (2), постобработка.

#### 6.2 Допустимый способ

1. WCS: `Room.unpublish()`
2. Бэк: очищает сессию, если сессий больше нет → статус → Участвовал (2).

### 7. Завершение звонка (администратор/организатор или любой участник 1-на-1)

```
POST /calls/dialog/:dialog/stop
POST /calls/:callId/stop
```

Бэк:
- Завершает все WCS-сессии
- Статусы: Участвовал (2) или Пропустил (8)
- Рассылает `cType 6` всем, `cType 6004` пропустившим
- Останавливает запись

### Постобработка

- Если нет сессий администраторов → звонок считается зависшим → автостоп через 30 секунд.
- Если организатор выходит → попытка назначить первого администратора организатором. Иначе — правило зависшего звонка.

## Типы сообщений (cType)

| cType | Код | Описание |
|---|---|---|
| 1 | TEXT_MESSAGE | Текстовое сообщение |
| 2 | AUDIO_CALL_STARTED | Начало аудиозвонка |
| 3 | VIDEO_CALL_STARTED | Начало видеозвонка |
| 4 | VOICE_MESSAGE | Голосовое сообщение |
| 5 | SYSTEM_MESSAGE | Системное сообщение |
| 6 | CALL_ENDED | Звонок завершён |
| 2001 | CALL_ACTIVATED | Звонок стал активным (появился собеседник) |
| 2002 | JOIN_CALL | Запрос на присоединение (от пользователя) |
| 2003 | LET_JOIN_CALL | Разрешение на присоединение (от админа) |
| 2004 | CALL_USERS | Вызов пользователей (новых или существующих) |
| 2005 | CALL_PARTICIPATE | Разрешение перехода из лобби (от админа) |
| 2006 | CALL_USER_STATE_SET | Обновление состояния пользователя |
| 2007 | CALL_USER_PERMITS_SET | Обновление разрешений пользователя |
| 2008 | CALL_USER_STATUS_SET | Обновление статуса участника |
| 6001 | CALL_DECLINED | Отклонение входящего звонка |
| 6002 | CALL_KICKED | Исключение пользователя из звонка |
| 6003 | CALL_START_MISSED | Пропущено начало звонка (поле `text` — сериализованный JSON со списком неответивших) |
| 6004 | CALL_END_MISSED | Пропущен звонок (рассылается только пропустившим окончание) |
